= 1.4.1 =
* Fixed: the opt-in notice could not be dismissed and came back on every page load
* Fixed: the opt-in notice now links straight to the opt-in screen, with accurate wording
* Fixed: leaving the opt-in screen without choosing left the notice up for good; opening the scanner settings now shows the opt-in screen again until you click Allow or Skip
* Fixed: on sites running other Fullworks free plugins, the opt-in notice and menu could belong to the wrong plugin
* Fixed: deleting the plugin now also removes its opt-in setting (FSS_form_rendered)
* Fixed: builds could bundle an Action Scheduler release that needs a newer WordPress than this plugin supports; it is now held at 4.1.x, which matches the WordPress 6.8 minimum
* Changed: updated the bundled opt-in library to 1.3.3

= 1.4.0 =
* Changed: Tested up to WordPress 7.1.
* Changed: Minimum WordPress version is now 6.8, required by the bundled Action Scheduler 4.1.
* Changed: Updated bundled libraries: Action Scheduler 3.9.2 to 4.1.0 and the Fullworks opt-in library 1.0.1 to 1.2.4. The 1.2.4 library no longer shows a duplicate advert when another Fullworks plugin is active.
* Changed: Translations are loaded by WordPress.org automatically; the plugin no longer calls `load_plugin_textdomain`.
* Fixed: "Translation loading for the fullworks-scanner domain was triggered too early" notice on WordPress 6.7 and later. Settings labels and the white-label title are now built after `init`.
* Fixed: The report table sort order was ignored. Clicking a column heading now sorts the report.
* Fixed: The summary email waited on the wrong job group, so it could be sent before plugin scans had finished.
* Fixed: The "auto update not working" check never found the recorded update time because of a stray space in the option name.
* Fixed: Network activation on a newly created site used a deprecated hook (`wpmu_new_blog`) and the wrong plugin file name.
* Fixed: Admin styles and scripts were registered under the version number instead of the plugin name.
* Fixed: The internal version constant was stuck at 1.1.1.
* Fixed: Re-scanning an issue that was already recorded updated the wrong row (the row count was used as the row ID).
* Fixed: The opt-in registration used the shortname `FSS-Free`, which the opt-in service does not recognise; it is now `FSS`. The first-visit opt-in prompt also now knows the settings page slug.
